1. PROJECT OVERVIEW
================================================================================

DataForge AI is a full-stack data analytics platform that allows any user —
regardless of programming experience — to upload a dataset and immediately
receive automated statistical analysis, machine learning model comparisons,
AI-generated narrative insights, and an intelligent LLM-powered chat interface.

The platform combines:
  - A Python/FastAPI backend for data processing, ML training, PDF export,
    and LLM streaming.
  - A React/Vite frontend with a polished dark/light UI built on Tailwind CSS.
  - Claude (Anthropic's AI) as the intelligence layer for chat and insights.

Users interact with their data entirely through a browser — no Python or coding
knowledge required.

================================================================================
2. GOALS & OBJECTIVES
================================================================================

Primary Goals:
  - Provide instant, zero-code exploratory data analysis (EDA) for any CSV,
    XLSX, or JSON dataset.
  - Offer a one-click ML model leaderboard so non-experts can identify the
    best-performing algorithm for their data.
  - Let users ask free-form questions about their data in plain English via an
    LLM-backed chat interface.
  - Generate a professional PDF report of the full analysis with one click.
  - Deliver a modern, accessible UI with dark and light mode support.

Secondary Goals:
  - Ensure data privacy — all processing happens in-memory with no persistence.
  - Make the codebase clean and deployable for free using Render + Vercel.
  - Provide safe secret management (API key never committed to git).

6. BACKEND — CORE MODULES
================================================================================

── core/loader.py ──────────────────────────────────────────────────────────────

  Responsibilities:
    - Reads raw bytes uploaded via the /upload endpoint.
    - Detects file format from the filename extension.
    - Parses CSV with Pandas read_csv(), XLSX with read_excel(openpyxl),
      JSON with read_json().
    - Returns a clean pandas DataFrame.
    - get_schema(df) inspects each column and returns:
        name, type (numeric / categorical / datetime / boolean),
        unique value count, missing value count.

── core/analyzer.py ────────────────────────────────────────────────────────────

  Responsibilities:
    - perform_eda(df) produces a JSON-serialisable dict containing:
        summary     : Descriptive statistics (count, mean, std, min,
                      25%, 50%, 75%, max) for all columns.
        correlation : Pearson correlation matrix for numeric columns.
        missing     : Missing value count per column.
        charts      : Up to 10 histogram bar charts (numeric distributions)
                      and up to 5 pie charts (categorical value counts).
        rows/columns: Dataset dimensions.

── core/insights.py ─────────────────────────────────────────────────────────────

  Responsibilities:
    - generate_insights(df) runs a series of deterministic checks and
      produces a list of insight objects: { type, title, text }.
    - Insight types: "success", "warning", "insight", "info".
    - Checks performed include:
        Missing value warnings (columns >5% missing).
        High-correlation pair detection (|r| > 0.8).
        Constant / near-constant column detection.
        Class imbalance detection for low-cardinality columns.
        Dataset size and feature count assessment.
        Data completeness badges.

── core/trainer.py ──────────────────────────────────────────────────────────────

  Responsibilities:
    - suggest_models(df, target_column): Returns problem_type and a ranked
      list of recommended models based on target column characteristics.
    - train_selected_models(df, models, target_column): Orchestrates training
      for all selected models.

  Training pipeline:
    Step 1 — _prepare_data():
      Builds feature matrix column-by-column (avoids pandas copy-on-write).
      LabelEncoder applied to categorical columns (<50 unique values).
      High-cardinality text columns are dropped.
      Datetime columns are excluded.
      Target column auto-classified as regression (numeric, >10 unique) or
      classification (categorical or low-cardinality numeric).

    Step 2 — Train/test split:
      test_size = max(0.15, min(0.25, 20 / n_rows))
      StandardScaler applied for SVM, KNN, Logistic Regression.

    Step 3 — Model training:
      Each model is instantiated, trained, and timed.
      Classification metrics: accuracy, F1, precision, recall.
      Regression metrics    : R², MAE, MSE.
      K-Means clustering    : silhouette score, n_clusters, inertia.
      CNN / RNN/LSTM        : marked as "not_applicable" (require image/
                              sequence data, not tabular CSV).

    Step 4 — Ranking:
      Supervised results sorted by primary metric (descending for most,
      ascending for MSE/MAE). best_model = top supervised result only
      (K-Means never overrides supervised models).

  Supported models (11):
    Linear Regression, Logistic Regression, Decision Tree, Random Forest,
    Naive Bayes, SVM, KNN, K-Means, CNN*, RNN/LSTM*, XGBoost
    (* = not_applicable for tabular data)

── core/exporter.py ─────────────────────────────────────────────────────────────

  Responsibilities:
    - generate_pdf_report(filename, schema, eda, insights, df) → bytes
    - Builds an A4 PDF using ReportLab Platypus:
        Cover header    : Branded dark background with gradient rule.
        Metadata row    : Filename, date, record count, feature count.
        Schema table    : Column name, type, unique count, missing count.
        Stats table     : Descriptive statistics for up to 15 columns.
        Data Quality    : Missing values table or "complete" badge.
        Sample Data     : First 8 rows, first 7 columns.
        AI Insights     : Each insight as a titled block with colour-coded
                          horizontal rule.
        Footer          : "Generated by DataForge AI · YYYY-MM-DD".

── core/chat.py ────────────────────────────────────────────────────────────────

  Responsibilities:
    - check_api_key() → validates ANTHROPIC_API_KEY presence and format.
    - _build_data_context() assembles a rich text prompt context block:
        Dataset name, row/column counts.
        Full schema listing with types and missing counts.
        Numeric descriptive statistics.
        Top 5 values for up to 5 categorical columns.
        Pearson correlation matrix (if ≥2 numeric columns).
        First 10 rows as CSV.
    - stream_chat_response() — async generator that:
        Builds the Anthropic messages array from multi-turn history.
        Calls claude-haiku-4-5-20251001 via client.messages.stream().
        Applies prompt caching (cache_control: ephemeral) on the system
        prompt to reduce latency and token costs on follow-up messages.
        Yields SSE chunks: "data: {\"text\": \"...\"}\n\n"
        Yields final:      "data: [DONE]\n\n"
        Handles AuthenticationError and RateLimitError gracefully.

9. FEATURE DESCRIPTIONS
================================================================================

9.1  FILE UPLOAD & PARSING
────────────────────────────
  Accepts CSV, XLSX (Excel), and JSON files up to ~50 MB via drag-and-drop
  or file browser. On successful upload the backend returns the full EDA
  result, schema, and first 10 rows preview. All other tabs unlock.

9.2  DATA PREVIEW
──────────────────
  Shows a schema grid (one card per column) and a paginated data table.
  Useful for verifying the file was parsed correctly and for understanding
  the structure and types before analysis.

9.3  AUTOMATED EDA
───────────────────
  Zero-config exploratory data analysis:
    - Descriptive statistics (mean, std, min, quartiles, max).
    - Missing value counts and percentages.
    - Histograms for up to 10 numeric columns.
    - Value-count pie/donut charts for up to 5 categorical columns.
    - Pearson correlation matrix (available for PDF export and chat context).

9.4  AI INSIGHTS ENGINE
────────────────────────
  Rule-based insight engine that scans the dataset and generates narrative
  findings. Examples: "High correlation detected between col_A and col_B",
  "Column X is 43% missing — consider imputation", "Dataset is complete —
  no missing values found". Results displayed as colour-coded cards.

9.5  ML MODEL TRAINING
───────────────────────
  User selects any combination of 11 models from a categorised grid.
  Optional AI suggestion auto-selects the best models based on the target
  column's data type and cardinality. The engine:
    - Preprocesses features (label encoding, NA imputation, scaling for SVM/KNN).
    - Splits into train/test sets (15–25% test, adaptive).
    - Trains each model and records timing.
    - Computes classification metrics (accuracy, F1, precision, recall) or
      regression metrics (R², MAE, MSE).
    - Returns a ranked leaderboard with percentage bars.

9.6  DASHBOARD
───────────────
  A business-intelligence style view with KPI cards (total records, features,
  quality score, data coverage), an area chart for numeric distributions,
  a composition pie chart, and multi-feature bar charts.

9.7  EXPORT TO PDF
───────────────────
  "Export Report" button in the header calls GET /export which triggers a
  full ReportLab PDF build server-side and streams it as a binary download.
  The PDF contains: branded header, schema table, statistical summary,
  data quality section, sample data, and AI insights.

9.8  CHAT WITH DATA (LLM PRO FEATURE)
───────────────────────────────────────
  Powered by Anthropic's Claude (claude-haiku-4-5-20251001):
    - Sends the full dataset context (schema, stats, correlations, sample rows)
      as a system prompt with prompt caching enabled for lower latency.
    - Supports multi-turn conversation (full history sent each request).
    - Streams responses token-by-token via Server-Sent Events.
    - Frontend renders markdown-formatted responses in real time.
    - Requires ANTHROPIC_API_KEY in backend/.env.

9.9  DARK / LIGHT MODE THEME SYSTEM
─────────────────────────────────────
  Full dual-theme system built with React Context + CSS custom properties:
    - Dark theme: deep navy (#080d18) backgrounds, slate borders, sky/violet
      accent colours.
    - Light theme: clean white cards with shadow-sm, slate-50 page background,
      same accent colours reading naturally on white.
    - Animated pill toggle (Moon/Sun icons) in the sidebar.
    - Preference persisted in localStorage ("df-theme").
    - Smooth 220ms CSS transitions on all color properties globally.
    - Chart colors (grid, axis, tooltip) switch via isDark conditional.

11. SECURITY & DATA PRIVACY
================================================================================

  Data Storage     : ALL uploaded data is held exclusively in Python's
                     in-memory dict (data_store = {}).  Nothing is written
                     to disk, a database, or any third-party storage.

  Data Lifetime    : Data is erased when:
                     (a) A new file is uploaded (overwrites the dict).
                     (b) The backend process is restarted.
                     (c) The server shuts down.

  External Calls   : The ONLY time user data leaves the server is when the
                     Chat feature is used — a text summary is sent to
                     Anthropic's API.  Raw file bytes are never forwarded.
                     Anthropic's API policy: data is not used for training
                     and is subject to their data retention policy
                     (~30 days).

  API Key Safety   :
                     - ANTHROPIC_API_KEY is stored in backend/.env.
                     - backend/.env is listed in .gitignore and was never
                       committed to the repository.
                     - backend/.env.example (safe template) is committed.
                     - For production (Render), the key is set via the
                       Render dashboard's environment variable panel.

  CORS             : Currently set to allow_origins=["*"] for development
                     convenience.  For a production hardening step, replace
                     "*" with the exact Vercel frontend URL.

  Input Validation : File-type validation in loader.py (extension check).
                     Pydantic models on all POST request bodies.
                     HTTPException raised with meaningful status codes.

15. KNOWN LIMITATIONS
================================================================================

  1. No Authentication:
     The backend has no user authentication. Anyone with the backend URL can
     upload files and overwrite the in-memory data_store. Suitable for
     personal/demo use; not for multi-user production.

  2. Single Dataset at a Time:
     data_store holds only one dataset. Uploading a new file replaces the
     previous one for all users hitting the same server instance.

  3. CNN & RNN/LSTM Not Trainable:
     These deep learning models are listed in the UI for educational awareness
     but are marked "not_applicable" for tabular data. They require dedicated
     image/sequence pipelines (TensorFlow/PyTorch).

  4. Render Free Tier Cold Starts:
     Free Render instances take ~30 seconds to wake after 15 minutes idle.
     Users may experience a brief delay on first interaction after inactivity.

  5. Large Dataset Performance:
     The EDA and ML training steps run synchronously in the FastAPI request
     handler. Very large datasets (>100k rows) may cause the request to time
     out on the free Render tier.

  6. Chat Requires Anthropic Credits:
     The Chat with Data feature requires a funded Anthropic API account.
     A valid API key with zero credit balance will return a billing error.

  7. PDF Export Uses Dark Theme Colors:
     The ReportLab PDF is hardcoded with the dark navy color palette to match
     the original brand design. It does not switch to match the user's current
     light/dark mode preference.
